# VisualPilot observer development conventions

These conventions record the user's requested workflow. They do not override later user instructions.

- Work in complete batches: corpus inventory, cause-based fixes, regression, one GitHub publication and consolidated report. Do not end after each card or require repeated "continue" for authorized work.
- Parallel agent work is authorized when the user requests it; give workers non-overlapping file ownership and integrate before final validation.
- Prioritize colored-face cards and operational table sizes. White-face support is deferred.
- Tests should run in the laboratory first. Accumulate necessary real PPPoker checks into one Windows session; never claim Linux/mocked tests are real Windows/Unity validation.
- Distinguish real source images, crops, synthetic scenes, transforms and independent evaluation. Hash/deduplicate sources; record abstentions and wrong accepted reads, not only successes.
- Keep capture/readers passive, no gameplay input. Unknown/ambiguous results must not be guessed. Do not lower thresholds simply to make a fixture pass.
- User deliverables must be published on GitHub with a working link, not workspace-only downloads.
- Do not write images continuously. Respect bounded diagnostic storage and memory-only observer mode.
- A missing sample blocks that case, not all unrelated work. Track unresolved 8h→3h explicitly until reproduced and fixed in the same color theme.
- Before ending a batch, execute regression, summarize before/after with limitations, and give one concrete list of remaining blockers. Do not promise execution continuing after the turn ends.
